# 배움 다지기 (수업 복습)

선생님이 그날 수업 내용을 넣으면 AI가 핵심 개념 카드와 문제 초안을 만들고, 선생님이 확인해 배포한 것만 학생이 푼다. 데일리 퀴즈(학년 공통 영어·연산 매일 반복)와 카드놀이(선생님이 만든 암기 세트)와 별개로, **오늘 수업에서 배운 것**을 다진다.

- 교사 `/teacher/lesson-review`, 학생 `/student/lesson-review`, API `/api/lesson-review/...`.

## 선생님

1. 과목·단원·차시 제목을 고르고 수업 내용을 글로 붙이거나 사진(4장, 브라우저에서 1600px JPEG로 줄임)·PDF(1개, 2.5MB)를 넣는다.
2. **AI로 초안 만들기**: 개념 3~6개, 개념에 연결된 문제 5~10개(4지선다·O/X), 문제마다 쌍둥이 문제를 만든다. 또는 **직접 만들기**로 같은 틀을 채운다.
3. 초안을 고친 뒤 **배포**한다. 배포한 복습은 고칠 수 없다(학생 답 기록이 문제와 어긋나지 않게). 숨기기·다시 보이기만 할 수 있다. 초안은 지울 수 있다.
4. 문제별 이해도 막대(완료 학생은 최종 체크, 진행 중 학생은 프리테스트 체크)와 학생별 진행 단계를 본다.
5. 보말 연결은 기본 꺼짐. 켜면 한 차시를 끝까지 마친 학생에게 10보말, 차시당 한 번(`pointLedger/lesson-review_{lessonId}`).

## 학생

1. **먼저 풀어 보기**: 답을 고르면 정답·해설이 나오고 완전이해·알쏭달쏭·완전모름 중 하나를 고른다. 틀린 문제는 완전이해를 고를 수 없다(서버도 알쏭달쏭으로 보정).
2. **개념 카드**: 알쏭달쏭·완전모름 문제에 연결된 개념만 카드로 나온다. 뒤집어 읽고 별을 모두 모으면 다음 단계가 열린다.
3. **다시 풀기**: 같은 문제가 아닌 쌍둥이 문제로 다시 풀고 다시 체크한다.
4. **완료**: 문제별 최종 체크(다시 푼 문제는 다시 풀기 결과) 중 완전모름은 7일 뒤, 알쏭달쏭은 14일 뒤 복습에 들어간다.
5. **오늘의 복습**: 예정일이 지난 문제를 하루 최대 10개. 원래 문제와 쌍둥이 문제를 번갈아 낸다. 완전이해가 두 번 연속이면 졸업, 아니면 다시 7일/14일 간격.

## 저장과 권한

- `classes/{c}/lessonReviews/{id}`: 개념·문제·정답(서버 전용), 상태 `draft|published|hidden`.
- `classes/{c}/students/{s}/lessonReviewRuns/{lessonId}`: 단계, 프리테스트·다시 풀기 답과 체크. 첫 답과 첫 체크는 바꿀 수 없다.
- `classes/{c}/students/{s}/lessonReviewItems/{lessonId}_{questionId}`: 복습 일정. 졸업하면 `dueDate`를 `9999-12-31`로 둬 조회에서 빠진다.
- `classes/{c}/settings/lessonReview`: 보말 연결.
- 클라이언트는 Firestore를 직접 읽거나 쓰지 않는다. 답을 내기 전에는 정답·해설을 보내지 않는다. 모든 학생 변경은 트랜잭션 안에서 학생 연결·비활성 상태를 다시 확인한다. 교사 API는 학급 소유를 확인한다.

## AI와 비용

- 기존 OpenAI 연결(`OPENAI_API_KEY`, `OPENAI_MODEL`)과 `runMeteredAi`의 선생님별 분·일 한도, 사용량·비용 집계(`aiJobs`, 도구 이름 `lesson-review`)를 쓴다.
- AI는 선생님이 초안을 만들 때만 한 번 호출한다. 학생 풀이·복습에는 AI를 쓰지 않는다. 사진·PDF가 많을수록 입력 토큰이 늘어난다.
- 자료 속 지시문은 데이터로만 다루도록 지시하고, 결과는 엄격한 JSON 스키마와 서버 검증(`validateContent`)을 모두 통과해야 저장된다.
- 교과서 사진·PDF는 초안 생성에만 쓰고 저장하거나 학생에게 보여 주지 않는다.

로컬 테스트: `node src/modules/lesson-review/run-tests.mjs` (전체 `npm test`에 연결).
