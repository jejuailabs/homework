# 학생별 기본 전시실

학생 코드 최초 발급 시 학생 문서의 `personalExhibition.createdAt`을 함께 저장한다. 전시실의 주인은 학생 ID이며 코드 재발급으로 전시실이 바뀌지 않는다. 기존 학생은 개인 전시실 첫 조회 시 같은 필드를 보완한다.

- 진입: 학생 교실의 **나의 전시실** 카드와 상단 메뉴 → `/student/my-exhibition`.
- 교사 일괄 업로드의 **작가명**에서 학급 학생의 번호·이름을 선택하면 기존 작품의 `studentId`와 표시 이름을 함께 지정한다. 미지정 작품은 학급 전시에 남으며 개인 전시실에는 나타나지 않는다. 동명이인은 번호로 구분한다. 기존 이름 판독 기능은 유일한 이름만 제안하며 교사가 선택을 바꾸면 늦게 도착한 판독 결과로 덮어쓰지 않는다.
- 학생 업로드는 기존 서버 검증대로 로그인한 학생에게 연결된다.
- 개인 전시실은 기존 전시실의 작품을 조회한다. 파일 복사, 별도 작품 원장, 새로운 공개 링크는 생성하지 않는다. 작품 연결 변경·상태 변경·교체는 다음 조회 때 반영된다.
- 기존 접근 정책에 따라 열린 전시와 지난 전시의 본인 작품만 모은다. 본인은 자신의 대기·보관 상태도 확인한다. 준비 중인 학급 전시는 학생에게 공개하지 않는다. 개인 전시실 API는 학생 본인의 로그인 세션을 사용하며 다른 학생 ID를 받지 않는다.
- 전시실 10개씩 페이지를 읽고 작품을 더 불러온다. 기존 학생 전시 목록 인덱스와 3D 전시 컴포넌트를 재사용한다. 학급 전시실 목록·공개 QR·아트북·보말 설정은 바꾸지 않는다.

기존 **학생당 전시실별 현재 작품 한 개** 정책은 유지한다. 같은 일괄 업로드에서 한 학생을 두 번 선택하면 저장 전에 안내한다. 이전 작품 버전을 보관하는 기능은 포함하지 않는다.

2026-10-23 검증: Node.js 24에서 전체 단위 검사 249개, 타입 검사와 운영 빌드 통과. demo Firebase에서 코드 발급·재발급, 실제 교사/학생 업로드, 학생 연결 변경, 미지정 제외, 권한과 페이지 이동을 검사했다. Chromium에서 실제 일괄 업로드 → 개인 전시실 반영, 늦은 이름 판독과 수동 선택의 충돌, 동명이인·중복 선택, 3D·확대창·초점 복귀, 320~430px 및 영어·어두운 화면을 확인했다. 가상 자료와 검증 기록은 커밋하지 않는 `.qa/`에 보관한다.
