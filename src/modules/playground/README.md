# 말놀이터

학생의 국어 놀이와 교사 진행 게임을 독립 모듈로 제공한다. 기본 문제와 정답은 서버에서만 읽는다. 이미지 생성/API 추론 없이 기존 아이콘과 CSS로 화면을 구성한다. 생성 이미지 요청서는 루트 `docs/playground-prompts.json`에 보존한다.

## 이용과 범위

- 학생: `/student/playground`, 넌센스·수수께끼·어휘·맞춤법 혼자 풀기, 힌트·해설·재연습, 맞춤법 복습, 학급 주간 순위, 친구 접속·초대, 1:1·2~4인 순발력·교사 팀전 참가.
- 교사: `/teacher/playground`는 탭 3개다. **출제하기**(① 항목별·랜덤·직접 고르기·많이 틀린 맞춤법 → ② 문제 수·시간·팀 수 → ③ 지금 함께 풀기(팀전) 또는 이번 주 혼자 풀기로 내기), **문제 보기**(항목별 둘러보기, 우리 반 문제 추가·수정·숨김), **설정·기록**(학급 설정, 참여·오답 리포트).
- 혼자 풀기는 항목마다 하루 10문제다. 그날 처음 열 때 학생·날짜별로 섞어 `playgroundYears/{schoolYear}/daily/{date}_{kind}`에 고정한다. 순서는 이번 주 목록의 안 푼 문제 → 안 푼 문제 → 이미 풀어 본 문제다. 10문제를 다 풀면 완료 화면을 보여 주고 다음 날 새로 고른다. 틀린 문제의 연습 다시 풀기와 맞춤법 복습은 이 10문제와 별도다. 4개 항목의 40문제가 모두 점수에 들어가도록 하루 점수 상한은 40이다.
- 이번 주 목록(`playgroundLists/{weekStart}.itemIds`)은 모든 항목을 60개까지 담는다. 학생 메뉴 카드에 남은 선생님 문제 수를 보여 준다. 팀전의 이번 주 범위도 같은 목록을 쓴다.
- 기본값: 학급 이용과 학생 대결, 보말 연결 모두 꺼짐. 교사가 설정에서 연다. 순위는 별도로 숨길 수 있다.
- 문제은행 `bank-v1`은 660문항의 개발 초안으로 명세의 목표 수량을 채웠다. 현장 교사 검수는 아직 이루어지지 않았다. 분포와 ID 보존 원칙은 `bank/README.md`를 따른다.
- AI 초안 생성과 생성 이미지 13종은 포함하지 않는다. 별도 과금 여부와 구체 비용 범위를 확인하고 명시적인 승인을 받은 뒤 진행한다.

## 기록과 권한

`classes/{classId}/settings/playground`에 설정, `playgroundItems`에 교사 문항, `playgroundLists/{weekStart}`에 주간 목록을 저장한다. 풀이 회차는 학생의 `playgroundYears/{schoolYear}/sessions`, 최초 답안은 `attempts`, 오늘의 10문제는 `daily`, 하루 상한은 `days`, 복습은 `spelling`, 주간 합계는 `playgroundScores/{weekStart}`에 저장한다.

회차 발급 시 문항 버전·정답·보기·시드를 서버에 보관한다. 클라이언트에는 공개 문제와 사용한 힌트만 보낸다. 제출한 `hintsUsed`를 신뢰하지 않으며 서버가 공개한 힌트 수로 채점한다. 회차·최초 답안·하루 합계·주간 합계·보말 장부를 하나의 트랜잭션에서 저장한다. 같은 요청과 동시 제출은 중복 적립되지 않는다. 이미 답한 문제는 연습이며 점수를 얻지 못한다. 한국 날짜를 사용하고 학년도는 3월에 바뀐다.

학생의 학급·학생 연결, 비활성 여부, `authVersion`을 변경 트랜잭션에서 재검사한다. 교사 문항과 설정은 `canManageClass`에 따라 소유 학급에만 쓴다. 모든 응답은 비공개·캐시 금지이며 변경 API는 Origin을 확인한다. 클라이언트는 Firestore에 직접 쓰지 않는다.

## 실시간 진행

서버 API가 방을 진행하고 참가자는 60초 읽기 권한으로 Firestore를 구독한다. 방 코드는 학급 내에서 원자적으로 예약한다. 정답과 원본 답안 경로는 클라이언트에서 읽을 수 없다. 교사는 참가자 기록을 읽을 수 있고 학생은 자신의 개인 기록만 읽는다.

구독이 거부되거나 끊기면(규칙 미배포, 읽기 권한 만료 등) 화면은 `GET rooms/{id}/state`를 1~2.5초 간격으로 조회하는 방식으로 자동 전환한다. 이 조회는 방 문서만 읽고, 문제 단계가 바뀐 때만 문제 문서를 다시 읽으며, 결과가 저장된 판에서는 멈춘다. 마감 시각이 지난 방은 조회한 참가자 누구의 요청으로든 서버가 진행하므로 특정 화면의 타이머에 의존하지 않는다. 구독이 가능하면 조회하지 않아 읽기 비용이 늘지 않는다. 1:1·순발력은 답안 접수 직후 서버가 조기 공개를 확인하고, 팀전은 교사 화면이 확인을 요청하며 서버가 다시 검증한다.

답안 시각은 서버 접수 시각으로 고정한다. 마감 뒤 500ms 유예가 끝나거나 연결된 참가자(30초 안에 응답, 기권 아님, 이번 문제 참여 가능) 전원이 답하면 정답을 공개한다. 1:1은 두 학생이 모두 연결되어야 시작하고, 순발력·팀전은 연결된 참가자가 둘 이상이면 시작한다. 시작 때 연결이 끊겨 있던 학생은 재접속한 다음 문제부터 참여한다. 순발력의 150ms 공동 순위는 공개 단계에서 확정한다. 보기의 표시 순서와 제출 ID를 분리한다. 팀전은 시작한 참가자 명단을 기준으로 팀 평균을 계산하며, 일시정지 전후 답안 점수를 보존한다.

명시적으로 나가면 그 판은 기권이다. 1:1에서는 상대의 몰수승으로 마치며 완주 보말은 지급하지 않는다. 방장이 임의로 일찍 종료한 판은 취소로 기록하고 승점·보말을 지급하지 않는다. 일시적인 연결 끊김은 30초 뒤 감지하고 재접속하면 다음 문제부터 참여한다. 1:1 종료 시 여전히 연결이 끊긴 학생은 기권으로 처리한다. 같은 상대와 하루 3판을 넘으면 대결 순위 점수를 추가하지 않는다. 보말은 승패와 관계없이 완주 기준이며 하루 최대 3개다. 교사의 팀전 보말은 별도 정산 영수증으로 한 번만 지급한다.

`PLAYGROUND_DISABLED=true`는 페이지·메뉴·API를 막고, `PLAYGROUND_LIVE_DISABLED=true`는 실시간 기능만 막는다. 기존 기록은 지우지 않는다. 오래 실행하는 게임 서버나 새 외부 서비스는 필요하지 않다.

## 정리와 배포

기존 `/api/cron/upload-cleanup` 호출에서 만료 방을 제한된 수만큼 정리한다. 비공개 답안·정답·개인 기록·읽기 권한 등 하위 문서를 지운 후 방 문서를 마지막에 지운다. Firestore TTL을 활성화하지 않으며 새 예약도 만들지 않는다.

로컬 테스트는 `node src/modules/playground/run-tests.mjs`로 실행한다. 전체 테스트에도 연결했다. 실서비스 읽기/쓰기·유료 AI·TTL 설정·호스팅 과금 테스트는 검증에 사용하지 않는다. 에뮬레이터와 브라우저 합성 시험 자료는 `.qa/`에 보관하고 커밋하지 않는다.

운영에는 앱뿐 아니라 `firestore.rules`의 신규 `playRooms` 읽기 규칙도 필요하다. GitHub 푸시로 발생하는 Vercel 자동 배포와 Firebase 규칙 반영은 로컬 구현 완료와 구분한다. 비용·무료 한도·초과 과금 조건 확인과 사용자 승인 없이 운영 사용을 활성화하지 않는다. 직접 Vercel 배포·수동 재배포는 사용하지 않는다.
