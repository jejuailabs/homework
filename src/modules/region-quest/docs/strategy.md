# 우리 학교 동네 탐험 RPG — 현장 니즈 조사와 구현 전략

작성일: 2026-10-27 · 대상: 초등 3~4학년 사회 '우리가 사는 곳' 영역 · 기반: 기존 `우리 동네 탐험` 도구 + `러닝킹` 게임 모듈 · 구현 지시서: [IMPLEMENTATION_BRIEF.md](../IMPLEMENTATION_BRIEF.md)

---

## 0. 한 줄 정의

**학교를 중심으로 실제 길과 장소를 한 번 정확하게 모아 '지역 팩'을 만들고, 그 한 벌의 데이터로 ① 교사용 백지도·약도 ② 아이들이 걸어 다니는 2D 픽셀 RPG ③ 학습지·평가 자료를 함께 만드는 도구.**

핵심은 "게임에서 걸은 길이 백지도에 그리는 길과 똑같다"는 점입니다. 게임과 수업 자료가 같은 좌표계를 쓰기 때문에 게임은 놀이에서 끝나지 않고 지도 읽기 수업으로 이어집니다.

## 1. 현장 교사의 페인포인트와 니즈 (조사 결과)

| # | 페인포인트 | 근거 | 이 제품이 답해야 할 니즈 |
|---|---|---|---|
| P1 | **지역화 수업 자료가 부족함.** 교사들은 3~4학년 지역화 단원 수업을 어려워하고, 자료 부족을 가장 시급한 문제로 꼽음 | 「2015 개정 사회과 교육과정 운영 실태와 개선 방안: 초등 3~4학년 중심」(KCI) | 우리 학교 주변 자료를 **자동으로 모아 주되 검수할 수 있게** 해야 함 |
| P2 | **교과서는 행정구역 단위라 아이들의 생활권과 맞지 않음.** 지역화 교과서의 위상이 바뀐 뒤 교사들이 자료집을 직접 만들고 있음 | 「초등 사회과 지역화 교과서 위상 변화 시기의 지역화 교육 실행 사례 연구」(한국지리환경교육학회지) | **학교 반경(생활권) 중심** 설계. 아이디어의 '학교 중심'이 연구 결과와 정확히 맞음 |
| P3 | **고장 모습을 알아볼 자료가 교과서·보조교과서 밖에서는 구하기 어려움.** 교사들은 구글 지도 캡처를 백지도에 옮겨 그리는 식으로 손수 만듦 | 「초등학교 3학년을 위한 지역화 학습 시스템 개발 및 적용」(한국정보교육학회), 공부하자.com 단원 안내 | 캡처·트레이싱 작업을 **원클릭 백지도·약도 생성**으로 대체 |
| P4 | **현장체험학습이 급격히 위축됨.** 초등교사 96.2%가 체험학습에 부정적(법적 책임 49.8%, 민원 37.0%). 서울 실시율 86%(2023) → 31%(2026) | MBC·중앙이코노미뉴스·오마이뉴스·한국교육신문 보도(초등교사노조 설문) | 직접 나가지 않아도 되는 **가상 고장 답사**, 또는 실제 답사 전 **사전 답사** |
| P5 | **디지털 지도 도구는 조작을 익히는 데 시간이 듦**(구글 지도 수업에서 기능 적응에 약 10분) | 쌤동네 구글 지도 수업 사례 | 조작은 **방향키와 클릭만**. 차시 안에 바로 몰입할 수 있어야 함 |
| P6 | **백지도는 수준별로 정보량을 달리 써야 함**(흑백 단순 백지도는 위치 쓰기와 형성평가용) | 「초등 사회과 학습을 위한 백지도의 개발과 활용」, 지학사 백지도 안내 | 같은 지역을 **정보량이 다른 여러 장**으로 출력(완성 지도 → 반 백지도 → 완전 백지도) |
| P7 | **에듀테크 개인정보 검증 부담이 교사에게 넘어옴**(학습지원 소프트웨어 수백 종을 교사가 확인) | 헤럴드경제 2026-02 보도 | **학생 위치·사진 수집 없음**, 기존 학급 계정 안에서 동작. 별도 가입 없음 |
| P8 | **자료 정확성.** 틀린 지역 정보를 가르치면 신뢰가 무너짐(교사 지역 지식의 편차) | 「사회과 지역 교과서의 활용 실태」(교사의 지역 이해 제고 제안) | 사실마다 **출처·기준일**, 교사 검수 전에는 학생에게 노출하지 않음 |
| P9 | **교사 업무 부담.** 한국 초등교사 42.8%가 학생 관리·변화 대응에서 높은 어려움을 겪음. 디지털 기술은 주로 수업 보조에 쓰임 | KEDI TALIS 2024 분석(한국교육신문) | **준비 10분 이내**를 목표로. 진도·결과가 학습지와 평가로 자동 정리되어야 함 |

### 교육과정 연결점 (2022 개정, 3~4학년군 '우리가 사는 곳')
- **[4사01-01]** 주변 여러 장소에서의 경험과 느낌을 다양한 방식으로 표현하고 장소감을 나눔 → 게임 속 **장소 일기·도감 카드**
- **[4사01-02]** 주변 장소를 살펴보고 더 살기 좋은 곳으로 만드는 방안을 탐색 → **"동네 고치기" 제안 퀘스트**
- 고장의 공공기관, 옛이야기와 인물, 문화유산과 관련된 성취기준은 NCIC 원문에서 코드와 문구를 확인한 뒤 퀘스트 태그로 매핑합니다(이번 조사에서는 문구를 직접 확인하지 못함).

### 조사 한계와 보완 방법
- 인디스쿨 같은 교사 커뮤니티 글은 로그인이 필요해 검색으로 확인하지 못했습니다. 논문과 보도 위주의 근거입니다.
- 게임·메타버스를 우리 고장 단원에 적용한 **효과 검증 연구는 찾지 못했습니다.** 기장군(메타버스 도로명주소 교육), 유성구(VR 스탬프투어) 같은 운영 사례만 있습니다. 시장은 비어 있지만 효과는 직접 증명해야 합니다.
- → **1단계에서 3~4학년 담임 5~8명과 인터뷰**: 실제 차시 흐름, 현재 쓰는 자료, 백지도 사용 방식, 가장 시간이 드는 작업을 확인합니다.

## 3. 핵심 설계 원칙

1. **데이터 한 벌, 출력 여러 개.** 지역 팩 하나에서 백지도·약도·게임 맵·학습지가 모두 파생됩니다. 교사의 검수도 한 번이면 됩니다.
2. **좌표가 진실.** 게임 타일맵은 실제 좌표에서 투영한 결과입니다. 북쪽이 위이고, 축척과 도로 연결(교차로)이 유지됩니다. 귀여움은 그 위에 입히는 스킨입니다.
3. **정확성은 등급으로 관리.** `자동 수집 → AI 요약 → 교사 검수 완료`. 학생 화면에는 검수 완료된 사실만 나갑니다.
4. **학생 데이터는 최소한으로.** GPS, 실사진, 실명 위치를 쓰지 않습니다. 교실에서 하는 가상 탐험입니다.
5. **40분 차시 단위.** 한 차시 = 한 구역 또는 한 퀘스트 묶음. 이어하기가 기본입니다.

## 4. 데이터 아키텍처

### 4.1 출처별 역할

| 데이터 | 1차 출처 | 비고·확인할 점 |
|---|---|---|
| 학교 위치 | 공공데이터포털 **전국초중등학교위치표준데이터**(한국교육시설안전원, 위경도 포함, 월 단위 병합) | 학교 검색 → 중심점 자동 설정 |
| 도로·보행로·건물 외곽·하천 | **OpenStreetMap**(현재 사용 중) | **ODbL**: 렌더링한 이미지는 출처 표시만 하면 되지만, 가공한 *데이터베이스*를 공개 배포하면 동일 라이선스 공유 의무가 생깁니다. 지역 팩을 교사 간에 공유할 때 유의 |
| 배경지도·교육용 백지도(보조) | **국토지리정보원 영상지도·배경지도 API**(공공누리 1유형 출처표시, 무료, *교육용 백지도* 레이어 포함), 수치지도 다운로드(NGII·국가공간정보유통) | **공간정보관리법상 국외 반출 제한** 때문에 해외 리전 서버(Vercel 기본 리전)에서 호출할 수 없다는 언급이 있음 → 서울 리전(icn1) 고정 또는 클라이언트 직접 호출 가능 여부를 확인해야 함 |
| 문화유산 | **국가유산청 문화재마스터위치정보 API**(공공데이터포털, 이용허락 제한 없음), 지정유산 지도 다운로드 | 지정 등급·명칭을 공식 명칭으로 표시 |
| 관광지 | **한국관광공사 TourAPI**(위치기반 조회) | 이용 조건과 이미지 저작권은 직접 확인 필요(이번 조사에서 미확인) |
| 행정관청·공공기관 | OSM `townhall/police/fire_station/post_office/library` + 행정표준코드·기관 주소 | 주민센터는 명칭과 위치 변경이 잦으므로 기준일을 표기 |
| 역사·인물·옛이야기 | **화이트리스트 출처만 사용**: 한국민족문화대백과, 디지털향토문화전자대전, 국가유산포털, 시·군 시사(市史)·교육청 지역화 자료 | AI는 요약만 하고 문장마다 출처를 붙임. 인물 평가처럼 논쟁적인 서술은 교사 검수를 필수로 함 |
| ❌ 카카오·네이버 지도 | 사용하지 않음(게임 지오메트리 용도) | 지도·로컬 API 결과의 저장·가공·타사 지도 위 표시에 제약이 있다는 개발자 문의가 반복됨 → 게임 맵의 원천으로 쓰지 않는 것이 안전 |

### 4.2 지역 팩 데이터 모델 (기존 `NeighborhoodPack` 확장안)

```ts
type RegionPack = {
  version: 2;
  school: {code: string; name: string; lat: number; lon: number};
  extent: {radiusM: number; polygon?: [number, number][]};    // 반경 또는 교사가 그린 생활권 경계
  projection: {originLat: number; originLon: number; metersPerTile: number}; // 게임과 지도가 공유하는 좌표계
  network: {nodes: Node[]; edges: Edge[]};                    // 보행 가능한 도로 그래프(교차로 위상 유지)
  areas: Area[];                                              // 건물 외곽, 공원, 하천, 논밭
  places: Place[];
  sourceLog: {source: string; url: string; retrievedAt: string; license: string}[];
};
type Place = {
  id: string; kind: 'office' | 'heritage' | 'tour' | 'nature' | 'market' | 'school' | 'story';
  name: string; lat: number; lon: number;
  facts: {text: string; sourceUrl: string; retrievedAt: string; status: 'auto' | 'draft' | 'verified'; verifiedBy?: string}[];
  curriculum: string[];          // 예: ['4사01-01']
  gameRole?: 'npc' | 'landmark' | 'collectible' | 'quest-hub';
  level: 1 | 2 | 3;              // 백지도 정보량 단계와 난이도
};
```

## 5. 지도 생성 파이프라인

```
학교 검색 → 생활권 범위 지정 → 수집(OSM·공공 API)
   → 정규화(이름 한글화, 중복 병합, 분류)
   → 도로 그래프 생성(교차로 노드 분할, 보행로·횡단보도 유지)
   → 교사 검수 큐(장소 포함/제외, 사실 승인, 누락 장소 직접 추가)
   → ┬ 벡터 약도 렌더러 → 스타일 N종 (SVG/PDF)
     └ 타일 변환기   → 픽셀 RPG 맵 (JSON 타일맵 + 충돌맵)
```

### 5.1 약도·백지도 스타일 (같은 벡터, 다른 스킨)
| 스타일 | 용도 |
|---|---|
| 교과서형 컬러 약도 | 수업 도입용 판서 |
| 단계별 백지도 L1/L2/L3 | 완성 지도 → 이름 빈칸 → 길만 남은 지도. 수준별 학습과 형성평가 |
| 그림지도(크레용·수채 느낌) | 3학년 그림지도 그리기 예시 |
| 픽셀 아트 | 게임 화면과 같은 모습. "게임에서 본 그 길" 연결 |
| 기호 지도 | 범례·방위표·축척 막대 연습 |

→ 단순화 정도(`simplifyMapLine`의 epsilon), 도로 위계별 굵기, 라벨 밀도만 바꿔도 대부분 구현됩니다. 모든 출력에 방위표, 축척 막대, 출처, 기준일을 자동으로 넣습니다.

### 5.2 픽셀 타일맵 변환 (길을 정확하게 만드는 법)
- **투영**: 학교를 원점으로 하는 로컬 미터 좌표(등장방형 근사, 반경 2km 안에서는 오차가 무시할 수준) → 1타일 = 4~6m 권장. 반경 1km면 약 400×400 타일이므로 청크 단위로 로드합니다.
- **도로**: 그래프 엣지를 타일에 래스터화하되 위계별로 폭을 정합니다(대로 3타일, 골목 1타일). **교차로 노드는 반드시 걸을 수 있는 타일로 강제**해 길이 끊기지 않게 합니다. 변환 후 BFS로 학교에서 모든 장소에 도달할 수 있는지 자동 검사합니다.
- **건물**: OSM 외곽선은 타일로 채우고, 랜드마크는 종류별 귀여운 스프라이트(시청, 소방서, 도서관, 정자, 오름 등)로 교체합니다. 외곽선이 없는 지역은 블록 안을 일반 주택 타일로 절차적으로 채웁니다.
- **자연**: 하천, 바다, 논밭, 공원은 영역 타일로 그립니다. 제주라면 돌담, 귤밭, 오름 같은 지역 타일셋 확장이 차별점이 됩니다.
- **학교 앞 안전**: 어린이보호구역과 횡단보도를 게임 안의 "건너기 규칙" 미니 상호작용으로 활용합니다(안전 교육 연계).

## 6. 게임 설계

> 설계 목표 두 가지
> - **아이 쪽**: 교사가 "어디 가 봐"라고 시키지 않아도 아이가 스스로 다음 장소로 걸어가고 싶어야 합니다.
> - **교사 쪽**: 게임이 끝나면 수업 결과물(완성 지도, 장소 일기, 평가 근거)이 저절로 남아야 합니다.
> 이 두 가지가 같은 장치에서 나오도록 설계합니다.

### 6.1 핵심 판타지: "지워진 우리 동네 지도를 되살려라"

- **세계관**: 장난꾸러기 바람 정령 *지움이*가 우리 동네 지도의 색과 이름을 날려 버렸습니다. 아이들은 *동네 지도 탐험대*가 되어 직접 걸으며 지도를 되살립니다.
- **화면 장치**: 게임의 *안개(fog of war)가 곧 백지도*입니다. 처음 화면은 길 윤곽만 있는 백지도 L3이고, 걸은 길은 선이 진해지며, 장소 임무를 마치면 그 장소에 색과 이름이 돌아옵니다.
- **수업 장치**: 게임이 끝날 때 아이 화면에 남은 지도가 곧 **"내가 완성한 우리 동네 지도"**입니다. 그대로 인쇄하거나 제출하면 됩니다. 교사가 따로 백지도 활동을 준비할 필요가 없습니다.
- 지역에 맞춰 세계관을 바꿉니다. 제주는 바람 정령, 내륙 도시는 지도 먹는 도깨비, 강가 마을은 물안개 식으로 템플릿 몇 개 중에서 고릅니다.

### 6.2 아이가 "알아서" 돌아다니게 만드는 동기 장치 5가지

| 동기 | 장치 | 아이가 느끼는 것 | 숨은 학습 |
|---|---|---|---|
| **호기심** | 안개 걷기, 지도 가장자리의 "?" 표시, 숨은 장소(용천수, 옛 성담) | "저 너머엔 뭐가 있지?" | 생활권의 공간 범위 |
| **수집** | 장소 도감 카드, 지역 스티커, 지도 색칠률 % | "도감 다 채우고 싶다" | 공공기관·문화유산의 이름과 역할 |
| **이야기** | 장소에서 장소로 이어지는 단서형 퀘스트 체인(6.4) | "다음 이야기가 궁금해" | 지역의 역사·인물, 옛날과 오늘날 |
| **성장** | 지도 능력이 곧 레벨업(6.3) | "나침반 생겼다!" | 방위·기호·축척 |
| **함께** | 학급 공동 지도, 우리 반 복원률 | "우리 반이 애월을 다 살렸다" | 장소감 나누기, 서로 존중 |

**스스로 다니되 헤매지 않게 하는 장치**
- **세 갈래 목표판**: 이야기 / 수집 / 탐험 목표를 항상 하나씩 띄우고, 아이가 고릅니다. 하나에 막혀도 다른 갈래가 있습니다.
- **탐험 일지의 다음 단서**: 2분 동안 진행이 없으면 가장 가까운 미완료 장소의 방향을 *방위로* 힌트로 줍니다. 예: "우체국은 학교에서 동쪽이야". 힌트도 학습 장치가 됩니다.
- **실패 상태 없음**: 생명이나 패배가 없고, 틀린 답은 "다시 생각해 볼까?"로 넘어갑니다. 시간 압박은 6.6의 해넘이 하나뿐입니다.
- **교사 경계선**: 교사가 정한 생활권 밖은 "아직 지도가 없는 땅"으로 막아 둡니다. 차시가 진행되면 넓혀 줍니다.

### 6.3 지도 능력이 곧 성장 시스템 (지도 리터러시 = 파워업)

능력을 하나 얻을 때마다 미니맵이 한 단계 진짜 지도에 가까워집니다. 지도 읽기 학습 순서가 그대로 게임 진행이 됩니다.

| 단계 | 획득 방법 | 생기는 능력 |
|---|---|---|
| 1. **나침반** | 학교 옥상 전망대에서 "바다는 어느 쪽?" 맞히기 | 미니맵에 방위표, NPC가 방위로 길을 알려 줌 |
| 2. **기호 렌즈** | 우체국·파출소·학교의 지도 기호 맞히기(기존 `matching-maker` 재사용) | 미니맵의 건물이 지도 기호로 바뀜, 범례 열림 |
| 3. **발걸음 자** | 학교 → 우체국 걸음 수로 거리 추정하기(애월 실측 약 285m) | 축척 막대, 두 장소 사이 거리 표시 |
| 4. **높이 눈** | 오름이나 전망 지점에 오르기 | 등고·지형 레이어(4학년 확장) |
| 5. **옛 지도 돋보기** | 이야기 체인 완료 | 같은 자리의 옛 모습 레이어(옛날과 오늘날 비교) |

### 6.4 이야기 퀘스트 체인 — 애월초 예시 (실측 데이터 기반)

애월초의 강점은 **학교 담장 자체가 문화유산**이라는 점입니다. 애월초 담장은 조선시대 애월진성의 성벽입니다. 애월진성은 제주특별자치도 향토유산 제19호이고, 1581년 돌성으로 쌓았으며, 1921년 성터에 학교가 들어섰습니다. "우리 학교 담장이 400년 넘은 성벽이었다"는 아이들에게 가장 강력한 출발점입니다.

**체인 「성담의 비밀」** (5~6차시 분량, 출처는 디지털제주문화대전·위키백과·한라일보이며 교사 검수가 필요함)
1. **학교 담장(0m)**: 담장 돌 틈에서 지움이가 떨어뜨린 *옛 지도 조각 1*을 발견합니다. "이 담은 원래 무엇이었을까?"
2. **애월우체국(도보 약 285m)**: 옛 편지를 배달해 달라는 의뢰를 받습니다. 주소 읽기와 도로명주소 체계를 배우고, 받는 사람 단서를 얻습니다.
3. **애월항(약 505m)**: 포구 사람 NPC가 바다를 지키던 성과 배 이야기를 들려줍니다. *조각 2*를 얻습니다.
4. **애월환해장성·해안(문화유산 데이터로 위치 보강)**: 바닷가 방어 유적을 비교하고 *조각 3*을 얻습니다.
5. **한담 해안 산책로 → 장한철 생가와 표해록 기적비(약 1.2km 서쪽)**: 표류했다가 돌아온 선비 장한철의 이야기와 표해록(제주도 유형문화재 제27호)을 만납니다. *조각 4*를 얻습니다.
6. **학교로 귀환**: 조각을 맞추면 *옛 지도 돋보기*가 열리고, 학교 자리에 성이 겹쳐 보입니다. 이어서 "옛날과 오늘날 우리 동네는 무엇이 달라졌을까" 장소 일기를 씁니다.

**공공기관 "하루 체험" 미니 퀘스트** (장소 종류별 템플릿이라 어느 학교에서나 자동 생성)
- 우체국 → 편지 배달(주소와 방위) · 파출소 → 잃어버린 물건 찾기(안전과 도움) · 읍·면·동 사무소 → 주민의 부탁 해결하기(행정 서비스) · 도서관 → 우리 동네 책 찾기 · 보건지소 → 건강 지키는 곳 · 항구·시장 → 동네 사람들이 하는 일

### 6.5 장소감과 "동네 고치기" (성취기준 직결)

- **장소 사진기** → [4사01-01]: 장소에서 픽셀 장면을 "찰칵" 찍고, 감정 스티커와 한 줄 일기를 남깁니다. 학급 갤러리(기존 기능)에 모여 서로 보고 댓글 이모지를 남깁니다.
- **불편 신호 찾기** → [4사01-02]: 교사가 정해 둔 지점(인도 없는 길, 어두운 골목, 쉼터 없는 버스정류장 등)에 "?" 신호를 둡니다. 아이가 무엇이 불편한지 고르고 해결 아이디어를 씁니다. 반 전체 아이디어는 기존 `class-poll`로 투표합니다.
- 불편 지점은 *자동으로 만들지 않습니다*. 실제 동네를 부정적으로 낙인찍지 않도록 교사가 고른 곳만 씁니다.

### 6.6 40분 수업 리듬 (교사 통제권)

| 시간 | 흐름 | 게임 장치 |
|---|---|---|
| 0~5분 | 교사 도입. 오늘의 목표 공지 | 교사 화면의 *함께 탐험 모드*로 오늘 열리는 구역 보여 주기 |
| 5~30분 | 자유 탐험 | 아이마다 목표판 3갈래, 힌트, 이어하기 |
| 30분 | 게임 속 **해넘이** | 하늘이 붉어지며 "학교로 돌아가자" → 자연스럽게 정리 단계로 넘어감 |
| 30~40분 | 정리 | 내 지도·장소 일기 저장. 우리 반 복원률을 전자칠판에 공개 |

- 교사 버튼: **모두 멈춤**, **모두 학교로 귀환**, **구역 열기/닫기**, **오늘 퀘스트만 보이기**
- 교사 화면에는 아이별 위치가 아니라 *진행 상태*(장소 수, 막힌 아이)만 보입니다. 막힌 아이에게는 힌트 하나를 원격으로 보낼 수 있습니다.

### 6.7 평가 근거 자동 수집

| 성취 요소 | 게임에서 남는 근거 |
|---|---|
| 방위·기호·축척 | 능력 획득 퀴즈 정답 기록, 방위 힌트 없이 도착한 비율 |
| 주요 장소와 기능 | 도감 카드 수, 공공기관 퀘스트 완료 |
| 장소감 표현 | 장소 일기, 사진기 기록 |
| 살기 좋은 곳 방안 | 불편 신호 해결 아이디어, 투표 결과 |
| 지도 표현 | 정리 단계의 *내가 완성한 지도*(이름 쓰기는 손으로) |

→ 학급 리포트(기존 `class-report`)에 성취기준별로 묶어서 보여 줍니다. 개인 포트폴리오 PDF로 출력할 수 있습니다.

### 6.8 아이 안전·접근성 원칙

- 실시간 GPS 없음, 아이 사진 없음, 아이 사이 자유 채팅 없음(정해진 이모지 반응만), 개인 주택·상호 이름은 표시하지 않음
- 대사는 한 번에 2~3줄, 3학년 어휘, 읽어 주기(TTS), 어려운 말에는 사전 말풍선
- 키보드·터치·클릭 이동 모두 지원, 색만으로 구분하지 않음
- 경쟁 순위 대신 학급 공동 목표(복원률)를 기본으로. 포인트 연동은 교사가 고를 수 있게

### 6.9 어느 학교든 자동으로 게임이 되는 콘텐츠 생성 규칙

| 장소 종류(데이터) | 자동 퀘스트 템플릿 | 교사가 할 일 |
|---|---|---|
| post_office, police, townhall, library, clinic | 하루 체험 퀘스트 | 대사 확인 |
| heritage(국가유산 API), memorial | 옛 지도 조각, 이야기 체인 연결 | **사실 검수(필수)** |
| harbour, marketplace | 동네 사람들이 하는 일 | 대사 확인 |
| peak(오름·산), viewpoint | 높이 눈, 방위 퀘스트 | 없음 |
| school(이웃 학교) | 이웃 학교 친구 NPC | 없음 |
| 교사 지정 지점 | 불편 신호, 숨은 장소 | 위치 지정 |

- AI는 *검수된 사실만으로* 대사 초안을 씁니다. 사실 없이 지어낸 역사 대사는 만들지 않습니다.
- 지역마다 고유한 타일셋을 씁니다. 예를 들어 제주는 밭담(돌담 밭), 귤밭, 초가, 용천수, 오름입니다. 이것이 "우리 동네 같다"는 느낌의 핵심입니다.

### 6.10 교사 페인포인트 해소 점검표

| 페인포인트 | 해소 장치 | 교사가 직접 하는 일 |
|---|---|---|
| P1 지역화 자료 부족 | 지역 팩 자동 수집 + 장소 종류별 퀘스트 템플릿(6.9) | 사실 검수만 |
| P2 행정구역 ≠ 생활권 | 학교 중심 생활권 경계, 차시별 구역 열기(6.2) | 경계 드래그 |
| P3 캡처·트레이싱 수작업 | 안개 = 백지도, 정리 단계에서 지도 자동 출력(6.1) | 없음 |
| P4 체험학습 위축 | 가상 답사 + 실제 답사 전 사전 답사 모드 | 동선 선택 |
| P5 도구 조작 학습 시간 | 이동은 방향키·터치·클릭뿐, 첫 화면부터 바로 걷기 | 없음 |
| P6 수준별 백지도 | 백지도 L1~L3 출력 + 게임 진행도에 따라 아이마다 다른 지도 | 단계 선택 |
| P7 개인정보 검증 부담 | GPS·사진·채팅 없음, 기존 학급 계정, 처리 항목을 한 장으로 안내 | 없음 |
| P8 자료 정확성 | 사실별 출처·기준일, 검수 전 비공개, 지어낸 역사 대사 금지(6.9) | 승인 클릭 |
| P9 업무·수업 통제 부담 | 해넘이 종료, 모두 멈춤·귀환 버튼, 평가 근거 자동 정리(6.6, 6.7) | 버튼 몇 번 |

## 7. 교사 워크플로 (목표: 준비 10분)

1. 학교명 검색 → 자동 중심 설정 → 반경 또는 생활권 경계 조정 (1분)
2. 자동 수집 결과 확인: 장소 목록에 *자동/초안/검수완료* 배지 (3분)
3. 사실 카드 검수: 출처 링크를 보며 승인, 수정, 삭제. 누락 장소는 지도를 클릭해 추가 (5분)
4. 출력: 백지도 PDF(L1~L3), 약도 스타일 선택, 게임 링크 또는 QR (1분)
5. 같은 학교·시군 교사가 만든 **검수 완료 팩을 불러오기** → 두 번째 교사부터는 1분

---

## 8. 기술 구현 방향

- **게임 런타임**: 러닝킹처럼 **iframe으로 격리된 Canvas2D 타일 렌더러**를 권장합니다. 타일맵, 스프라이트, 충돌, 카메라 정도면 엔진 없이도 충분하고 번들이 가볍습니다. 저사양 크롬북과 태블릿에서 60fps를 목표로 합니다. 기능이 커지면 Phaser 같은 엔진 도입을 검토합니다.
- **저장**: 지역 팩 메타데이터는 Firestore, 큰 지오메트리와 타일맵 JSON은 Storage에 두고 버전·기준일로 관리합니다. 학생 진도는 기존 journey-storage 패턴을 따르되 학급 단위로 서버에 동기화합니다.
- **수집 서버**: 기존 `/api/neighborhood/map` 확장. Overpass 미러 정책(현재 private.coffee)은 그대로 유지하고, 결과를 캐시해 같은 학교를 다시 조회할 때 재사용합니다. 국토지리정보원 API는 서울 리전 함수 또는 클라이언트 호출로 분리합니다.
- **에셋**: 16×16 또는 32×32 픽셀 타일셋과 캐릭터 시트를 하나의 아트 디렉션으로 통일합니다. 기존 캐릭터·아바타와 톤을 맞춥니다.
- **접근성**: 키보드와 터치 모두 지원, 큰 글씨 대사, 색각 이상을 고려한 지도 팔레트.

## 9. 단계별 로드맵

| 단계 | 기간(가늠) | 산출물 | 완료 기준 |
|---|---|---|---|
| **0. 검증** | 2주 | 교사 인터뷰 5~8명, 시범 지역 3곳(제주시 도심 / 읍·면 농어촌 / 수도권 아파트 단지) 데이터 품질 점검 | 지역마다 OSM 도로·건물 커버리지 리포트, 핵심 차시 흐름 확정 |
| **1. 지역 팩 v2** | 3주 | 학교 검색, 생활권 경계, 공공 API 수집기, 검수 큐 | 교사 한 명이 10분 안에 팩을 검수 완료 |
| **2. 약도 스타일 엔진** | 2주 | 백지도 L1~L3, 교과서형, 그림지도, 픽셀 스타일 PDF·SVG | 교사가 실제 수업에 인쇄해서 사용 |
| **3. 걷기 MVP** | 3주 | 타일 변환기, 이동, 충돌, 미니맵, 장소 도착 시 대사, 도감 5곳 | 학교에서 모든 장소까지 도달 가능(자동 검사), 한 학급 시범 수업 |
| **4. 수업 연결** | 3주 | 퀘스트 유형 4종, 백지도 스티커 연동, 학급 리포트, 함께 탐험 모드 | 한 단원(6~8차시)을 게임으로 운영 |
| **5. 확산** | 이후 | 교사 간 팩 공유(같은 시군), 지역 타일셋 확장, 사전 답사 모드 | 두 번째 교사의 준비 시간 1분 이내 |

## 10. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| OSM 데이터가 농어촌에서 빈약함. **애월초 실측으로 확인**: 도로는 충분하지만 건물·토지 이용과 문화유산이 크게 비어 있음([애월초 측정 리포트](aewol-osm-measurement.md)) | 도로는 OSM, 건물은 공공 건물 데이터 또는 절차적 채우기, 문화유산은 국가유산 API + 교사 추가 |
| 단순 타일 변환 시 길 끊김·바다 번짐(실측에서 재현됨) | 4방향 연결 래스터화, 해안선 장벽 마스크, 변환 후 도달 가능성 자동 검사를 파이프라인에 필수로 넣기 |
| 운영 중인 Overpass 미러가 응답하지 않을 수 있음(측정 중 로컬에서 시간 초과) | 학교별 결과 캐시 + 한국 지역 OSM 추출본(Geofabrik 등)을 자체 처리하는 방식으로 전환 검토 |
| 라이선스(ODbL 공유 의무, 공공누리 출처표시, 국외 반출 제한) | 출력물마다 출처·기준일 자동 삽입, 팩 공유 기능 출시 전 라이선스 점검 |
| AI 환각, 인물 서술의 민감성 | 화이트리스트 출처 + 문장 단위 인용 + 교사 승인 전 비공개 |
| 실제 동네라서 생기는 안전·사생활 문제 | 개인 주택이나 상호를 라벨로 쓰지 않음(공공시설 위주), GPS 미사용, 실사진 대신 픽셀 그림 |
| 게임이 놀이로만 끝남 | 모든 퀘스트를 성취기준 태그에 연결하고, 결과물은 반드시 백지도·장소 일기로 남김 |
| 기기 성능 편차 | 청크 로딩, 타일 아틀라스, 저사양 모드 |

## 11. 성공 지표

- 교사 준비 시간(목표 10분 이하, 공유 팩은 1분)
- 단원 사전·사후 지도 읽기 평가(방위·기호·장소 위치) 점수 변화
- 백지도 장소 위치 정답률, 장소 일기 작성률
- 교사 재사용률(다음 학기·다음 단원에도 다시 쓰는지)
