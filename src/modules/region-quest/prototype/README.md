# 장난감 마을 — 첫 번째 플레이 테스트

2026-10-27 선택한 장난감 마을 스타일을 실제로 걸어 다니며 확인하는 작은 실험입니다. 애월 지형을 본뜬 지도가 아닌 **가상의 바람마을**이며, 편지 심부름 역시 조작 검증용 이야기입니다.

## 실행

프로젝트 루트에서 Node.js로 실행합니다. 설치, 별도 서버 계정, 환경변수, 외부 서비스가 필요하지 않습니다.

```powershell
node src/modules/region-quest/scripts/serve-prototype.mjs
```

<http://127.0.0.1:8787>에서 플레이합니다. 종료는 터미널의 Ctrl+C입니다. 포트가 사용 중이면 `$env:REGION_QUEST_PORT = '8788'`로 다른 포트를 정하고 실행합니다. 소스 변경 후에는 서버를 재시작하고 브라우저를 새로고침해야 합니다.

## 지금 시험할 수 있는 것

- 고정 시점의 장난감 마을과 투명 배경의 2D 캐릭터. Blender 모델 없이 정면·왼쪽·오른쪽·뒷면 각 3프레임으로 걷습니다.
- 바닥/목표물 클릭, 방향키/WASD, 화면 방향 버튼으로 이동합니다. 건물·바다 쪽으로는 이동 영역을 제한했습니다.
- 모모와 플레이어의 발밑 크기를 합친 충돌 영역을 적용했습니다. 방향키로 밀어도 모모를 통과하지 않고, 클릭 이동은 모모를 피해 우회합니다. 대각선 입력은 막히지 않은 축으로 이동합니다. 별도 물리엔진 없이 기존 이동과 경로 탐색이 같은 충돌 정보를 사용합니다.
- `길 안내`를 누르면 현재 미션 목표로 걸어가 대화를 엽니다. 가까이에서는 `E`나 대화 버튼을 쓸 수 있습니다.
- 모모와 대화 → 편지 찾기 → 우체통의 선택형 대화 → 이야기 카드 획득까지 한 미션이 이어집니다. 잘못된 선택에는 힌트를 줍니다.
- `학교로` 또는 H로 귀환하고 `탐험 계속`으로 출발 전 위치·방향·미션 상태를 복원합니다. 귀환 중에는 미션 진행과 이동이 멈춥니다.
- 미니맵에 현재 위치가 표시됩니다. 큰 지도를 눌러 바닥으로 이동할 수 있습니다. 지역 간 워프는 아직 없습니다.
- `캐릭터 보기`에서 네 방향을 동시에 보며 걷기/정지를 비교합니다.
- 진행은 같은 브라우저·같은 주소의 localStorage에 저장됩니다. 새로고침으로 이어가며 `처음부터`로 시험 진행을 초기화합니다.

## 다음 확장 전에 확인할 점

1. 캐릭터 크기·귀여움·방향 전환과 짧은 걷기 애니메이션이 원하는 느낌인지 확인합니다. 현재 3프레임은 조작 검증용이며 정식 버전에서는 프레임 수와 동작 일관성을 보강합니다.
2. 배경은 한 장으로 굽혀진 이미지입니다. 카메라 회전, 건물 내부 진입, 건물 앞뒤 가림, 개별 물체 편집은 구현하지 않았습니다. 실제 애월 지도는 배경·건물·장식 레이어와 충돌 데이터로 나누어 제작해야 합니다.
3. 실제 애월의 장소·거리·이동 경로와 학습 자료를 정하고, 한 장소의 대화형 학습 미션을 먼저 붙입니다.
4. 검증 후 지역 팩·여권·발견한 지점 워프·다른 지역으로의 이동 및 학급 배정을 기존 구현 지시서에 맞춰 연결합니다.

이번 테스트판은 Next.js 페이지, 학급, 로그인, Firebase, 포인트에 연결하지 않습니다. 서버는 127.0.0.1에만 열리며 게임은 `sandbox="allow-scripts"` iframe 안에서 실행됩니다. 호스트가 검증한 메시지만 로컬에 저장하고, 게임의 외부 통신은 CSP로 차단합니다. 브라우저 저장이 차단된 경우 현재 창에서 계속할 수 있지만 재방문 복원은 되지 않습니다.

## 코드와 에셋

| 파일 | 역할 |
| --- | --- |
| `game.html`, `game.css`, `game.js` | 화면, 캔버스 렌더링, 대화와 조작 |
| `model.js` | 이동·경로 탐색·미션 상태·귀환·저장값 정규화 |
| `world.js` | 실제 보행 영역, 장소·NPC 위치, 캐릭터 발밑 충돌 범위 |
| `host.html` | 게임 iframe과 로컬 저장 연결 |
| `../scripts/serve-prototype.mjs` | 템플릿과 이미지를 메모리에서 조립하는 로컬 서버 |
| `assets/manifest.json` | 이미지 이름과 3열×4행 프레임 규격 |
| `assets/generation.json` | 이미지 생성 프롬프트와 가공 기록 |

이미지는 Codex 내장 이미지 생성으로 만들었습니다. 생성 원본은 커밋하지 않고, 런타임에서 사용하는 최종 크기의 배경 WebP와 투명 PNG만 포함합니다. `../scripts/prepare-prototype-assets.mjs --background <원본> --player <원본> --npc <원본>`으로 에셋을 다시 패킹할 수 있습니다. 이 가공 단계는 프로젝트의 `sharp`를 사용하며 외부 호출은 없습니다. 캐릭터는 알파 실루엣을 검출해 공통 크기로 맞추고 발 기준점을 `(80, 192)`로 정렬합니다.


경로 우회, 이동 영역, 얇은 벽 통과 방지, 방향, 잘못된 저장 데이터, 미션 순서, 반복 귀환과 이어하기를 검증합니다. UI는 브라우저에서 미션 완료, 새로고침, 귀환/복귀, 네 방향 캐릭터를 직접 확인합니다.
