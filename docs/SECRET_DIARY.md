# 복구 가능한 비밀일기장

## 제공 기능

- 잠금 해제 후 월간 마음 달력. 한국 날짜 기준으로 날짜 선택, 여러 장 작성, 연월 이동.
- 종이 위 텍스트 입력, 한글 입력, 필압·획 보정 손글씨, 형광펜·연필, 획 지우기, 확대, 되돌리기.
- 기분 스티커 6종, 무료 꾸미기 10종, 5~10보말 상점 10종. 기존 구매는 보존.
- 기기 내부 한국어 음성 인식이 설치·지원되는 브라우저에서만 음성→글 사용. 외부 음성 API와 자동 유료 대체는 없다. 언어팩 자동 설치도 하지 않는다.
- 선택한 페이지를 현재 학급 소유 교사에게 별도 사본으로 공유. 이후 비공개 수정은 사본에 반영하지 않는다. 학생이 공개 취소할 수 있으나 이미 내려받거나 촬영한 내용은 회수하지 못한다.
- 월별 PDF(한 번 120장), 편집용 암호화 백업(파일당 1,000장 / 복호화 내용 32MiB), 가져오기는 새 ID로 만든 사본.
- 새 계정 연결 코드와 기존 일기 잠금번호를 함께 사용한 보관함 승계. 같은 계정은 학급 소속 변경 후에도 같은 보관함을 쓴다.

## 보호 범위

`personalDiaries/{vaultId}`는 학급 경로 밖에 있다. `users/{uid}.diaryVaultId`가 현재 소유자를 연결한다. 학생 로그인과 별개로 6자리 잠금번호를 확인하며 PIN은 salt를 포함한 scrypt 해시로만 보관한다. 5회 실패하면 15분 대기한다.

페이지 원문, 제목, 기분, 배치, 필기 데이터와 이전된 첨부물은 전용 키로 AES-256-GCM 암호화한다. 조회를 위한 월·수정시각·소유 연결·사용량은 서버 메타데이터로 남는다. 이것은 서버 관리형 암호화다. 운영 인프라에서 키와 데이터에 접근하는 주체까지 기술적으로 차단하는 종단 간 암호화가 아니다. 운영 관리자 UI에는 비공개 원문 조회 기능이 없다.

잠금 세션은 HttpOnly/SameSite=Strict 쿠키이며 운영 HTTPS에서 Secure를 사용한다. 기본 로그인 쿠키·학생 UID·인증 버전·잠금 버전과 연결되고 절대 만료는 20분이다. 잠금·복구·승계 시 기존 권한은 무효화된다. 클라이언트는 5분 미사용 또는 문서가 숨겨질 때 잠근다. 서버 연결 실패 때도 화면을 가리고, 저장 실패 초안은 메모리에서 유지하되 민감한 DOM은 제거한다. 다시 잠금 해제 후 저장을 재시도할 수 있다. 브라우저 종료 전 미저장 경고가 표시된다. 오프라인 영구 초안 저장 기능은 제공하지 않는다.

기존 `/api/my-space/diary` API는 닫고 사진·작품 API도 일기 잠금을 요구한다. 공개된 전시 작품의 원본 공개 상태까지 변경하지 않는다. 기존 사진 보관함 원본도 중복 이용·보존을 위해 자동 삭제하지 않는다.

학생 로그인 코드를 가진 사람이 최초 잠금 설정을 선점할 가능성은 학생 계정 인증 자체의 한계다. 초기 사용은 본인과 함께 진행하고, 의심 시 아래 복구 절차를 사용한다. "누구도 절대 못 본다"는 문구를 사용하지 않는다.

## 운영 활성화 전 필수 작업

1. 사용자에게 Vercel/Firebase의 배포·요청·읽기/쓰기·저장·전송 비용, 현재 무료 한도와 초과 조건을 확인해 설명하고 해당 범위의 명시적 승인을 받는다. 기술적인 크기 제한은 무료 사용 보장이 아니다.
2. 운영 환경의 `DIARY_ENCRYPTION_KEY`에 전용 32바이트 난수의 base64 값을 설정한다. 코드·로그·클라이언트·Git에 키를 노출하지 않는다. 미설정이면 안전하게 비활성 상태를 반환하고 원문 저장으로 대체하지 않는다.
3. 키는 데이터와 별도의 승인된 비밀 보관 장소에 백업하고, 접근 담당자 및 복구 절차를 기록한다. 시험 데이터로 백업된 키를 사용한 복호화 복구를 검증한다. **학생 PIN 초기화는 운영 암호화 키 분실을 복구할 수 없다.**
4. 기존 데이터가 있으면 키 값을 임의로 교체하거나 제거하지 않는다. 현 버전은 키 자동 교체 기능을 제공하지 않는다. 교체에는 기존 키로 복호화→새 키로 재암호화→전체 검증하는 별도 이전이 필요하다.
5. 지정된 복구 담당자만 기존 `admin`/`superadmin` 역할을 갖도록 관리한다. 일반 교사에게 관리자 역할을 주어 우회하지 않는다.
6. 변경을 커밋·푸시한 뒤 GitHub 연동 Vercel 자동 배포로 반영한다. CLI/API/대시보드 직접 배포·수동 재배포는 사용하지 않는다. 커밋·푸시·운영 배포 상태를 따로 확인한다.

## 잠금번호 분실 복구

학생 화면에서 복구 요청 → 운영자 `/admin/diary-recovery`에서 별도 본인 확인 및 사유 기록 → 30분 유효 일회용 코드 발급 → 학생이 자신의 로그인 화면에서 코드와 새 PIN 입력. 원문은 관리자에게 반환하지 않고 기록을 유지한다. 학생 상태 화면에는 복구 사실이 표시된다. 요청·발급·완료를 기록한다.

교사의 학생 로그인 코드 재발급만으로 일기 잠금을 해제하지 않는다. 복구 코드 자체가 있으면서 현재 학생으로 로그인할 수 있으면 재설정할 수 있으므로, 담당자가 요청자 본인을 별도로 확인해야 한다. 관리 화면에 다른 학생의 PIN이나 원문은 표시하지 않는다.

## 기존 기록 이전과 학년 승계

최초 설정/잠금 해제 때 기존 학급 아래 최대 60장의 일기를 암호화해 복사한다. 사진·전시작품은 보관함 전용 암호화 사본을 만든다. 모든 복사와 일치 확인이 끝난 뒤 기존 평문 일기 문서를 삭제한다. 실패하면 원본은 남고 재시도로 이어간다. 기존 서비스 백업에 남은 평문은 서비스의 백업 보존 정책에 따라 별도 관리해야 한다.

학년이 바뀌어 새 UID를 받는 경우 자동 이름 매칭을 하지 않는다. 이전 계정에서 일기 잠금을 풀고 30분 유효 일회용 연결 코드를 만든 뒤, 새 계정의 **새 일기장을 만들기 전** 첫 화면에서 코드와 기존 PIN을 입력한다. 보관함 소유 연결과 소유 스티커가 승계되고 이전 계정 권한은 해제된다. 기존 명시적 공유본은 그대로 남으며 새 계정에서 취소할 수 있다.

이전 계정이 먼저 정지·삭제되면 연결 코드 발급을 할 수 없다. 운영자의 별도 본인 확인에 의한 계정 재연결은 이번 버전에 포함되지 않는다. 학년 전환 때 기존 계정을 닫기 전에 승계하거나 백업을 제공해야 한다. 보관함 데이터는 학급 삭제 경로 밖에 보존되지만, 보존이 로그인 접근권 복구를 의미하지는 않는다.

## 내보내기와 제한

PDF는 학생 기기에서 생성한다. 종이·글·필기·이미지를 합성하므로 열람·인쇄용이며, PDF에서 글을 다시 편집하는 기능은 없다. 일반 PDF에는 앱의 잠금이 적용되지 않는다. 기기 내부에서 만들어지며 원문을 외부 변환 서비스에 전송하지 않는다.

백업은 별도 10자 이상 비밀번호로 PBKDF2-SHA256/AES-GCM 암호화한다. 앱의 복구 PIN과 다르며, 백업 비밀번호를 잃으면 그 파일은 운영자도 복구할 수 없다. 앱 원본은 여전히 PIN 복구 대상이다. 현재 사진·전시작품이 포함된 편집용 백업은 손실 방지를 위해 거절하고 PDF나 계정 연결을 안내한다. 가져오기는 유료 스티커 소유권을 부여하지 않으며, 현재 보유하지 않은 아이템이 포함되면 저장 전에 안내한다. 여러 페이지 가져오기는 페이지마다 저장하므로 네트워크 중단 시 완료 장수를 알리고 중복 가능성을 안내한다.

페이지당 500조각, 획당 2,000점·페이지당 20,000점, 텍스트 조각 6,000자·페이지 합계 30,000자, 페이지 JSON 최대 600KB를 검증한다. 보관함은 10,000장·공유 100개·암호화 저장량 256MiB 한도를 적용한다. 한도는 일기·공유본·이전된 첨부물에 함께 적용된다. 한도 초과는 원문을 버리거나 덮어쓰지 않고 오류로 안내한다.

## 로컬 검증

`npm run typecheck`, `npm test`, `npm run build`를 사용한다. 비밀일기 전용 테스트는 아래와 같으며 Firebase·Storage·계정 서비스를 메모리 대역으로 바꾸어 유료 호출을 하지 않는다.

- `node src/modules/my-space/run-tests.mjs`: 기존 꾸미기 및 달력·문서 검증
- `node src/modules/my-space/run-diary-server-tests.mjs`: 암호화, 변조, PIN 제한, 세션, 복구, 승계, 공개 사본·취소, 용량 제한, 경로 권한
- `node src/modules/my-space/run-diary-export-tests.mjs`: 스티커 자산, 백업 왕복·변조·암호 오류·중단

손글씨의 실제 펜 지연·필압·손바닥 오입력은 사용 기기의 펜 하드웨어에서 추가로 확인해야 한다. 로컬 모의 브라우저 검증은 실제 펜 필기감이나 모든 기기의 음성 인식을 보장하지 않는다.
