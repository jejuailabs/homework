# 숙제 파일 일괄 다운로드 · 비우기 · 14일 보관

선생님이 숙제 제출 파일을 숙제별 ZIP으로 받고, 받은 뒤 파일을 비워 저장공간을 확보하는 기능이다. 비운 파일은 바로 지우지 않고 14일 동안 보관하며, 그 사이에는 복원할 수 있다.

## 선생님 흐름

1. **받기**
   - 숙제 화면의 `파일 받기·정리` 버튼을 누르면 그 숙제 하나를 받는다.
   - 숙제 목록에서 `선택`으로 여러 숙제를 고른 뒤 `선택 숙제 파일 받기`를 누르면 최대 20개까지 받는다.
   - 숙제마다 ZIP 하나가 따로 저장된다. 예: `받아쓰기 3단원_10-29.zip`
   - ZIP 안의 파일 이름은 `03_김민준_원래파일명`이다. 이전 제출 파일은 `이전 제출/` 폴더에 들어간다.
2. **비우기**
   - ZIP으로 받은 숙제만 비울 수 있다.
   - 받은 뒤 새로 제출된 파일이 있으면 다시 받아야 비울 수 있다.
   - 비우기 전에 확인 창에서 숙제 수, 파일 수, 용량, 복원 가능 날짜를 보여 준다.
3. **보관과 복원**
   - 비운 파일은 학생과 선생님 화면에서 바로 사라진다.
     - 학생 화면에는 "선생님이 정리한 파일이에요"가 보인다.
     - 선생님 숙제 화면에는 "N일 보관 중 · M월 D일에 완전히 지워져요 [복원]" 안내가 뜬다.
   - 14일 안에 `복원`을 누르면 그대로 되돌아온다.
4. **완전 삭제**
   - 14일이 지나면 매일 도는 정리 작업(`/api/cron/upload-cleanup`)이 Storage에서 지운다.
   - 지우는 대상은 원본, 썸네일, 영상 처리 전 원본이다.

## 저장공간 계산

- 비우는 순간 업로드 상태가 `submitted`에서 `trashed`로 바뀐다. 그래서 선생님 저장공간 사용량에서 **바로 빠진다**.
- 플랫폼 Storage에서는 14일 뒤에 실제로 줄어든다. 보관 기간의 비용은 플랫폼이 부담한다.
- Google Cloud Storage 버킷의 **소프트 삭제(7일)**가 켜져 있다(2026-10-29 확인). 그래서 앱이 지운 뒤에도 7일 더 과금 대상으로 남는다.
  - 앱 보관 14일과 버킷 보관 7일을 더해, 비운 뒤 실제로 용량이 사라지기까지 최대 약 21일이 걸린다.
  - 앱에서 이미 14일을 보관하므로 버킷의 소프트 삭제는 줄이거나 끄는 것을 검토할 수 있다. 바꾸려면 운영자 결정이 필요하다.

## 데이터

| 위치 | 내용 |
|---|---|
| `uploads/{id}` | `status: 'trashed'`, `trashedAt`, `purgeAt`, `trashedBy`. 14일이 지나면 `status: 'purged'`, `purgedAt` |
| `submissions/{assignmentId_studentId}` | `filesRemoved: {trashedAt, purgeAt}`. 이 표시가 있으면 서버가 파일 주소를 발급하지 않는다 |
| `homeworkFileArchives/{assignmentId}` | 마지막으로 받은 시각과 받은 파일 목록(`downloadedUploadIds`), 비운 시각, 삭제 예정일, 파일 수, 용량 |
| `adminAudit` | `homework.files-trash`, `homework.files-restore` |

- API: `POST /api/assignments/files`
  - 받는 값: `action` (`status` · `files` · `downloaded` · `trash` · `restore`), `assignmentIds`
  - 학급 주인 선생님만 사용할 수 있다. 보관(숨김)된 숙제도 대상이다.
- 학생이 다시 제출하면 제출 기록이 새로 쓰여서 `filesRemoved` 표시가 사라지고, 새 파일은 정상적으로 보인다.

## 제한과 운영 조건

- ZIP은 선생님 브라우저에서 만든다. 서버 비용과 Vercel 실행 시간 제한이 없다.
  - 숙제 하나의 파일 합계가 1.5GB를 넘으면 `내 저장공간 > 전체 내보내기`를 안내한다.
- 브라우저가 Storage 파일을 직접 받으므로, **버킷 CORS의 GET 허용 목록에 서비스 도메인이 있어야 한다.**
  - 현재 허용 목록: `ourclass.co.kr`, `www.ourclass.co.kr`, 기존 `*.vercel.app` 주소
  - 새 Vercel 주소(`homework-mu-seven.vercel.app`)는 목록에 없다. 그 주소에서 미리 시험할 때는 다운로드가 실패한다. 도메인을 옮긴 뒤에는 `ourclass.co.kr` 기준으로 동작한다.
- 여러 숙제를 받을 때 크롬은 처음 한 번 "여러 파일 다운로드 허용"을 묻는다.

## 향후 유료 옵션: 보관 기간 연장

기본 보관 기간은 14일이다(`HOMEWORK_TRASH_KEEP_DAYS`, `src/lib/homework-archive.ts`). 이 기간을 늘리는 것은 **유료 옵션으로 제공할 수 있다.**

- **예시 상품**: 30일, 90일 보관. 학교나 학년 단위 계약에는 1년 보관.
- **구현 방향**
  - 선생님 또는 학교의 요금제에 `trashKeepDays`를 두고, 비우는 시점에 `purgeAt`을 그 값으로 계산한다.
  - 이미 비운 파일의 `purgeAt`은 바꾸지 않는다. 요금제가 바뀌어도 기존 약속을 지키기 위해서다.
  - 선생님 화면의 "N일 보관" 문구와 확인 창의 날짜는 이미 `purgeAt` 기준으로 표시되므로, 계산만 바꾸면 된다.
- **비용 기준**: 보관 중인 파일은 Storage 요금이 그대로 나온다. 연장 기간 × 보관 용량에 버킷 소프트 삭제 7일을 더해 원가를 계산한다.
- **주의**: 보관 기간을 줄이는 변경은 이미 비운 파일에 소급하지 않는다.
