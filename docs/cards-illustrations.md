# 카드놀이 단어 그림

기본 어휘 3,000개에 투명 SVG를 연결한다. 세트·학습 도구의 순서, 정답 채점, 학습 기록, 게임 점수, 키보드 조작은 기존 구현을 유지한다. 홈페이지의 파스텔 토큰·캐릭터·6개 팔레트와 다크 모드를 사용한다.

## 표시 규칙

- 암기: 단어 옆에 그림. 선택한 그림의 뜻은 답을 공개한 뒤에만 표시한다.
- 리콜·스펠·오답 복습: 답 확인 이후에만 그림을 표시한다.
- 학생·교사 단어 목록과 기본 어휘 미리보기: 작은 그림과 기존 단어·뜻을 함께 표시한다.
- 짝 맞추기: 영어 앞면만 그림을 표시한다. 뜻 타일에는 그림을 붙이지 않는다.
- 단어 비: 떨어지는 카드의 크기·속도·판정은 그대로이며, 종료 후 놓친 단어 목록에 그림을 표시한다.
- 문장 퍼즐: 단어 세트의 예문 문제에 해당 단어 그림을 표시한다. 문장 세트는 자동 매칭하지 않는다.
- 교실 화면: 앞면과 뒷면이 모두 공개된 경우에만 그림을 표시한다. 지명 퀴즈는 정답 공개 후에만 표시한다.
- 시험: 새로운 그림 힌트를 추가하지 않는다.

‘그림 보기’는 해당 브라우저의 `cards-illustrations-v1` 설정이다. 모든 카드 화면에서 동기화하고, 끄면 원래 텍스트만 표시한다. DB나 세트 스냅샷은 변경하지 않는다.

## 단어와 뜻 매칭

`src/lib/card-illustrations.ts`가 정규화한 전체 영단어와 그림의 선택된 한국어 뜻을 대조한다. 원본 기본 어휘의 전체 뜻 또는 선택된 뜻이 일치할 때만 표시한다. 부분 단어·문장·연습문제·미등록 단어·다른 뜻은 그림을 붙이지 않는다. 예를 들어 `run / 달리다`는 그림이 있지만 `run / 운영하다`에는 붙이지 않는다.

그림은 3,000개 단어의 제작 시안이다. 동의어·관련 단어에는 공통 소재가 재사용되고, 추상어·문법어·다의어는 교육적 의미 검수가 필요하다. `src/data/card-illustrations.json`에 선택한 뜻과 검수 분류를 보존한다. 그림 자체가 정답을 대신하지 않는다.

## 자산과 비용

**그림 원본은 Firebase Storage에 보관한다. 웹사이트의 `public/`·Git 저장소·Vercel 배포물에 넣지 않는다.** 로컬 원본은 별도 제작 산출물로 보관하고, 업로드 준비본과 영수증은 Git 및 배포에서 제외된 `.qa/card-illustrations/`에 둔다. `.gitignore`와 `.vercelignore`에도 잘못된 `public/cards/vocabulary-*/` 복사본을 제외하는 규칙을 추가했다.

3,000개 SVG는 약 27.3MB, 파일당 평균 약 9.1KB다. 앱에는 단어·뜻·파일명 메타데이터와 `src/data/card-illustration-storage.json`의 작은 배포 설정만 들어간다. 화면에서 필요한 파일만 Firebase의 다운로드 주소로 지연 로딩한다. Next 이미지 최적화·Vercel 프록시·실행 시 `getDownloadURL()` 조회는 사용하지 않는다.

공개 교육용 그림에만 공유 다운로드 토큰을 사용한다. 이 토큰은 공개 URL의 일부이며 관리자 인증키가 아니다. 기존 학생 자료·개인 파일에는 적용하지 않으며 Storage Rules나 버킷 IAM을 변경하지 않는다. URL을 아는 사람은 그림을 다운로드할 수 있으므로 다운로드에 사용량 비용이 발생할 수 있다.

**2026-11-08 운영 버킷 `book-9b8ce.firebasestorage.app`의 `cards/vocabulary/v1/`에 3,000개를 업로드하고 한 장씩 크기·해시·토큰을 대조한 뒤 설정을 `ready: true`로 켰다.** 설정이 꺼져 있으면 이미지 요청 없이 텍스트 카드를 표시한다. 이미지 로드 실패 때도 단어·뜻과 기존 조작은 유지된다. 설정 파일 변경의 웹사이트 반영은 코드 배포로 하며, 이미지 자체는 배포하지 않는다.

업로드 중 Windows에서 로컬 영수증(`receipt.json`) 교체가 간헐적으로 `EPERM`으로 실패해 수백 장마다 멈췄다. 스크립트는 교체를 짧게 재시도하고, 멈출 때 오류 코드(응답 본문은 아님)를 표시하도록 고쳤다. 영수증 덕분에 다시 실행하면 이미 올린 객체는 메타데이터만 대조하고 이어서 올린다.

Firebase 저장 용량, 객체 생성·조회, 다운로드 전송량은 별도 과금될 수 있다. 버킷의 리전·플랜·남은 무료량을 확인하지 않았으므로 추가 비용 0원으로 간주하지 않는다. 저장·다운로드는 이후에도 사용량에 따라 과금될 수 있다. 아래 업로드 실행은 서비스·범위·비용 조건을 설명하고 사용자의 명시적인 승인을 받은 뒤에만 한다. 로컬 준비·기본 dry-run은 인증·네트워크 호출을 하지 않는다.

## 로컬 준비와 승인 후 업로드

로컬 제작 묶음을 준비하는 명령:

```sh
node scripts/sync-card-illustrations.mjs /absolute/path/to/vocabulary-svg-3000
node scripts/upload-card-illustrations.mjs --bucket book-9b8ce.firebasestorage.app
```

첫 명령은 원본 해시·파일명·정적 SVG 여부를 확인하고 줄 끝 공백만 정리하여 `.qa/card-illustrations/svg/`에 준비한다. `upload-plan.json`에는 최종 파일별 크기와 SHA256을 저장한다. 승인된 샘플 10개의 그림도 그대로 포함한다. 두 번째 명령은 기본적으로 오프라인 검증만 한다.

비용 및 공개 다운로드 범위를 승인받은 후에만 실행하는 명령:

```sh
node scripts/upload-card-illustrations.mjs --bucket book-9b8ce.firebasestorage.app --upload --approve-billing
```

승인 후 실행할 때만 `.env.local`의 기존 관리자 인증을 로드한다. 새 객체는 `cards/vocabulary/v1/<원래 파일명>`에 저장하고 `I.svg`처럼 대소문자를 보존한다. `image/svg+xml`, 1년 불변 캐시, 다운로드 토큰과 SHA256을 첫 업로드에 함께 지정한다. 생성 조건으로 기존 객체 덮어쓰기를 막는다. 재실행 시 같은 로컬 영수증의 토큰과 계획을 유지하고, 이미 존재하는 객체는 메타데이터가 일치할 때만 인정한다. 3,000개 모두 성공한 후에만 설정의 `ready`를 켠다. 일부 실패로 설정을 켜지 않는다.

이미 게시한 버전의 객체는 바꾸지 않는다. 그림 수정 시 새 `cards/vocabulary/vN` 경로를 사용하고 새 업로드 계획을 만든다. 업로드 스크립트에는 웹사이트 커밋·푸시·배포 동작이 없다.

2026-11-08 운영 반영 때 `vercel.json`의 `git.deploymentEnabled` 임시 항목(`codex/cards-illustrated` 자동 배포 끔)을 제거했다. 운영 배포는 `main`의 GitHub 연동 자동 배포만 사용한다.

2026-11-08: 3,000개 뜻 매핑, Firebase URL 조립·파일명 대소문자, 미업로드 상태의 텍스트 대체, 배포 폴더에 SVG가 없음을 오프라인 검사했다. 기존 카드 테스트와 전체 TypeScript 검사도 수행한다. 로컬 그림을 사용한 실제 컴포넌트의 임시 가짜 학급에서 암기 Space/Enter, 리콜 숫자키, 스펠 입력, 답 공개 전 그림 가림, 그림 끄기 동기화, 학생·교사 목록, 짝 맞추기, 문장 퍼즐, 단어 비 시작/일시정지, 모바일·다크 모드를 확인했다. 임시 페이지는 배포 코드에 포함하지 않는다.
