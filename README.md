# 모두의 숙제 · 숙제와 함께 자라는 우리 반

교사의 과제 생성·검사와 학생의 간단한 제출, 교사가 사진으로 운영하는 학급 작품전시 웹앱입니다. 고양이 모찌, 강아지 두부, 햄스터 콩이, 알파카 구름, 토끼 토리, 수달 모아가 함께합니다.

**숙제·교사용 AI 도구·작품전시와 전체 파스텔 디자인을 운영에 반영했습니다.** [운영 사이트](https://homework-indol-gamma.vercel.app) · [선생님 대시보드](https://homework-indol-gamma.vercel.app/teacher) · [작품전시 바로가기](https://homework-indol-gamma.vercel.app/teacher/exhibitions) · [GitHub](https://github.com/jejuailabs/homework). 전체 학급 대시보드, 과제별 제출·검사, 캐릭터 성장, 별도 어드민을 제공합니다. 과거 시점의 추이와 학습 게임은 후속 범위입니다.

## 로컬 실행

1. **Node.js 24.12.0 이상의 24.x와 npm**을 준비합니다. 현재 Firebase 13 계열 의존성의 요구 조건에 맞춘 기준이며, 로컬 번들 Node는 24.19, Vercel 런타임은 24.x를 사용합니다. `package.json`의 실행 기준을 함께 확인합니다.
2. 의존성을 설치합니다.

   ```sh
   npm install
   ```

3. 아래 환경 변수 안내에 따라 로컬 환경을 설정합니다. `.env.local`과 서비스 계정 파일은 Git에 추가하지 않습니다.
4. 개발 서버를 실행합니다.

   ```sh
   npm run dev
   ```

터미널에 표시된 로컬 주소에서 앱을 엽니다. Firebase 환경이 준비되지 않은 상태를 실제 로그인·저장 성공으로 해석하지 않습니다.

## 환경 변수

사용자가 지정한 Firebase 프로젝트는 `book-9b8ce`입니다. 웹 앱의 실제 설정 값은 해당 프로젝트에서 확인합니다. 아래 예시는 변수 이름만 안내하며 서비스 계정 키를 포함하지 않습니다.

### 브라우저용 Firebase 설정

```dotenv
NEXT_PUBLIC_FIREBASE_API_KEY=<Firebase 웹 앱 API key>
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN=<Firebase 웹 앱 auth domain>
NEXT_PUBLIC_FIREBASE_PROJECT_ID=book-9b8ce
NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET=<Firebase 프로젝트의 실제 bucket 이름>
NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID=<Firebase 웹 앱 sender ID>
NEXT_PUBLIC_FIREBASE_APP_ID=<Firebase 웹 앱 app ID>
```

Firebase 웹 설정은 클라이언트가 사용하는 식별 설정입니다. **서비스 계정 개인 키와 다른 값**이며, 웹 설정을 숨기는 것만으로 데이터 접근 권한이 보호되는 구조를 사용하지 않습니다. 데이터 접근은 서버 인증·권한 검사와 저장소 규칙으로 통제합니다.

### 서버 설정

```dotenv
FIREBASE_PROJECT_ID=book-9b8ce
FIREBASE_STORAGE_BUCKET=<Firebase 프로젝트의 실제 bucket 이름>
EXHIBITION_STORAGE_LIMIT_BYTES=5368709120
```

서버 프로젝트·버킷 값은 대응하는 `NEXT_PUBLIC_FIREBASE_*` 설정을 사용할 수 있지만, 운영 환경에서는 연결 대상을 명확히 확인합니다.

작품전시의 교사별 보관 한도는 기본 5GiB입니다. 원본·관람 이미지·썸네일과 미완료 업로드 예약을 함께 계산하며 서버 환경 변수로 조정합니다. 교사가 올린 원본을 보존하고 관람에는 압축 이미지를 사용합니다. 만료·실패 업로드는 실제 파일 삭제 후 예약 용량을 반환합니다.

서버 인증은 다음 중 환경에 맞는 한 방식을 사용합니다.

- **로컬:** `GOOGLE_APPLICATION_CREDENTIALS`에 저장소 밖에 둔 서비스 계정 JSON 파일의 절대 경로를 지정합니다.
- **배포:** 비공개 서버 환경 변수 `FIREBASE_SERVICE_ACCOUNT_JSON`에 서비스 계정 JSON을 안전하게 제공합니다.
- 관리되는 실행 환경에서 Application Default Credentials를 제공하는 경우 서버 구성에 맞춰 사용할 수 있습니다.

`FIREBASE_SERVICE_ACCOUNT_JSON`이 설정되어 있으면 서버는 이를 우선 사용하도록 구성합니다. 파일 경로 방식으로 실행할 때 의도하지 않은 이전 JSON 환경 변수가 남아 있지 않은지 확인합니다.

서비스 계정 JSON을 README, 소스 코드, `NEXT_PUBLIC_` 변수, 공개 정적 파일, 터미널 출력 또는 API 응답에 넣지 않습니다. 키 파일 내용 자체를 확인용 로그로 출력하지 않습니다.

## Firebase 준비

- Authentication에서 Google 로그인을 사용하도록 구성합니다.
- Firestore와 Firebase Storage를 준비하고 프로젝트·버킷 설정이 일치하는지 확인합니다. 대상 Storage 버킷의 위치는 `ASIA-NORTHEAST3`(서울)로 확인되었습니다. 이는 다른 Firebase 제품의 위치까지 확인했다는 의미는 아닙니다.
- 로컬·Preview·Production의 실제 인증 사용 도메인을 확인합니다.
- 숙제 앱 컬렉션의 Firestore 클라이언트 직접 접근을 막고, 서버 API의 인증·소유·소속 검사를 적용합니다.
- 같은 프로젝트의 기존 `bookData` 앱이 사용하는 명시적 허용 규칙은 정확히 보존합니다. 기존 앱의 동작을 바꾸거나 해당 허용 범위를 숙제 앱 컬렉션에 확대하지 않습니다.
- Storage 업로드는 서버가 승인한 사용자·경로·크기·타입 범위에서만 허용합니다.
- 규칙 파일을 실제 프로젝트에 적용하고 검증하기 전에는 앱 코드에 파일이 존재한다는 이유로 보호가 적용됐다고 간주하지 않습니다.

Google 로그인 후 서버 `__session` 쿠키와 브라우저 Firebase 인증을 함께 사용합니다. 로그아웃은 두 상태를 함께 종료해야 합니다.

언어·테마는 localStorage `homework-preferences`에 저장하며 인증 쿠키와 별개입니다. 현재 브라우저에 적용되는 설정으로, 언어·테마용 서버 쿠키나 언어별 URL을 사용하지 않습니다.

## 첫 플랫폼 운영자 등록

플랫폼 어드민은 일반 교사의 학급 관리와 별개입니다. Google 로그인만 했다는 이유로 운영자 권한이 생기지 않습니다.

1. 지정한 계정의 Firebase Auth 사용자가 있는지 확인합니다. 이미 이메일 검증된 Google 로그인 사용자라면 기존 UID를 사용합니다. 계정이 없을 때 앱에 Google 로그인하여 사용자를 만듭니다.
2. 관리용 실행 환경에 서버 인증 정보를 제공합니다.
3. 실제 Firebase Auth 계정을 대상으로 부트스트랩을 실행합니다.

   ```sh
   npm run admin:bootstrap -- --email jejuailabs@gmail.com
   ```

직접 실행 형태는 다음과 같습니다.

```sh
node scripts/bootstrap-admin.mjs --email jejuailabs@gmail.com
```

스크립트는 이메일로 사용자를 조회하고 이메일 검증 여부를 확인한 뒤 해당 UID에 `superadmin` 역할을 부여하는 용도입니다. 공개 웹 API로 노출하지 않습니다. 실행 결과와 역할 기록을 실제로 확인한 후 `/admin` 접근을 검증합니다.

운영자는 기본적으로 계정·학급 메타데이터와 운영 상태를 봅니다. 학생 제출물 전체 열람은 기본 권한이 아닙니다. 일반 수업 API에서는 운영자도 자신이 소유한 학급만 관리하며, 전체 학급의 운영 메타데이터는 별도 어드민 API로 제공합니다.

2026-10-13 검증: 정책 단위 테스트 34개(숙제·AI·전시 합산)를 통과했습니다. 로컬 `demo-homework` 에뮬레이터에서 작품 25점을 실제 등록한 통합 검사 12개가 통과했고, 3D 작품벽 4개를 이동하며 25점 모두 열 수 있음을 확인했습니다. 앞서 수행한 업로드·관리·예약 용량·페이지네이션 검사도 별도 기록으로 보관합니다. 프로덕션 빌드를 실행한 로컬 서버에서는 헤더·기능 카드의 전시 진입과 390px·320px 영문 다크 화면을 확인했고 페이지 런타임 오류는 0건이었습니다. 이 로컬 실행의 Google Fonts 요청은 샌드박스 네트워크 제한으로 차단되어 대체 글꼴로 검사했습니다.

같은 날 **실제 운영 전시 검증 5개도 통과**했습니다. 기존 QA 테스트 학급의 비공개 초안에서 48,882바이트 캐릭터 사진을 업로드하고, 중복 없는 처리·관람용 서명 이미지·학생 업로드 차단을 확인했습니다. 원본 다운로드 토큰은 처리 후 제거되고 이전 토큰 URL은 거부됐습니다. 이 검증이 만든 전시실·작품·업로드 기록·파일만 정리하고 실제 사용·예약 용량을 트랜잭션으로 차감했습니다. 실제 학생 작품은 사용하지 않았습니다. 로컬 근거는 `.qa/exhibition-25-results.json`, `.qa/exhibition-25-browser-results.json`, `.qa/delight-navigation-smoke-results.json`, 운영 근거는 `.qa/exhibition-production-smoke-results.json`입니다. `.qa`는 비공개 검증 기록으로 Git에 포함하지 않습니다.

전시실을 25개로 제한하지 않습니다. 교사는 학급 건물 안에 25개 이상 만들 수 있고, 목록은 커서 페이지로 이어서 조회합니다. 기본 관람은 **학급 건물 → 교실의 주제별 포스터 → 큰 전시실 모달** 순서입니다. 한 방의 세 벽에 **25점을 동시에 배치**하며 최대 32점까지 같은 공간에 전시합니다. 전시실당 최대 300점 중 32점을 넘는 작품은 다음 관으로 이어집니다. 실제 사진 액자 클릭·이동·둘러보기와 별도 관리 목록을 제공하며, WebGL을 사용할 수 없으면 접근 가능한 작품 목록으로 전환합니다. 사진 보관은 위의 교사별 용량 한도를 따릅니다.

3D 액자의 서명 이미지에는 저장소 CORS 설정도 필요합니다. `storage.cors.json`은 이 앱의 운영 주소 3개에 GET/HEAD 및 참여보드 서명 업로드 PUT을 허용하는 설정이며, 현재 운영 버킷에 반영했습니다. 기존 CORS 항목이 있으면 병합하고 버킷 메타데이터 버전 조건으로 갱신합니다. Firebase 배포 명령이 이 파일을 자동 적용하지는 않습니다. 공개 접근·IAM·Storage 보안 규칙을 허용하는 설정은 아닙니다.

건물·전시실 포스터·작품의 이름은 실제 3D 표지판에 한 번만 표시합니다. 원근과 무관하게 겹쳐 떠 있던 화면용 제목 버튼을 제거했고, 액자·건물·포스터 자체의 클릭·터치와 ‘모두 보기’ 목록의 키보드 선택을 유지합니다. 글자 캔버스와 표지판의 가로세로 비율을 맞추며 긴 이름은 압축하지 않고 말줄임하거나 포스터에서 두 줄로 표시합니다. 전체 제목은 작품 상세에서 확인할 수 있습니다. 이름표 크기와 25점 배치는 유지합니다.

교사 로그인은 `/teacher` 대시보드로 연결됩니다. 상단에 **대시보드 · 숙제 · 작품전시 · 참여보드 · AI 도구함**을 분리하고, 로고도 대시보드로 돌아갑니다. 대시보드는 기본으로 전체 학급·전체 기간을 보여주며 학생·과제·확인할 숙제·검사 완료·미제출·전시실 현황, 학급별 완료율, 최근 전시실과 참여보드를 제공합니다. 확인할 숙제를 누르면 해당 학급·과제·확인 전 필터가 선택된 검사 화면으로 연결됩니다. 운영자는 같은 대시보드의 운영자 메뉴에서 `/admin`으로 이동합니다.

교사의 `숙제` 메뉴는 `/teacher/homework`에서 반 선택과 숙제 목록을 먼저 표시합니다. 목록은 제목·제출 방식·마감일·제출 인원 요약 필드만 조회하며 학생 명단·답변·첨부파일은 읽지 않습니다. 과제를 클릭하면 해당 숙제의 학생별 검사판을 열고, ‘숙제 목록으로’ 버튼으로 돌아갑니다. 학생 명단은 ‘학생 관리’나 ‘과제 만들기’를 누를 때 조회합니다. 대시보드에서 특정 숙제를 직접 선택한 경우에는 해당 과제·상태의 검사판으로 이어집니다. 큰 소개 배너와 솔루션 소개 카드는 없으며 제출·미제출·재제출·검사 완료 수는 검사판의 상태 필터에 표시합니다.

새 과제는 생성할 때 제출 방식을 반드시 선택합니다. **텍스트 작성**은 답변 입력만, **이미지 업로드**는 사진 촬영·이미지 선택만, **영상 업로드**는 영상 촬영·영상 선택만 제공합니다. 이미지·영상은 해당 파일이 최소 1개 필요하고 설명은 선택입니다. 업로드 시작·제출 확정 API에서도 유형을 검사합니다. 기존 유형 미지정 과제는 `자유 제출`로 표시해 종전의 글·사진·PDF·영상 제출을 유지하며 저장된 과제나 제출 기록을 변경하지 않습니다. 교사와 학생 모두 영상 재생과 원본 열기를 제공합니다.

학생 명단은 `1. 김민서`, `1 김민서`, `1) 김민서`, `1번 김민서`처럼 한 줄에 한 명씩 입력하거나, `번호,이름` CSV 및 엑셀의 두 열을 복사한 탭 구분 붙여넣기로 등록합니다. 잘못된 줄·중복 번호는 원래 입력의 행번호로 알려주며, 오류가 있는 명단을 일부만 등록하지 않습니다. `.xlsx` 파일을 직접 읽는 기능은 없습니다. 현재 첨부 정책은 파일당 사진·PDF 100 MiB, 지원 영상 250 MiB, 제출당 최대 10개이며 무제한 저장 서비스를 의미하지 않습니다.

## Vercel 배포 대상과 확인

### 참여보드

교사는 `/teacher/boards`, 학생은 `/student/boards`에서 자기 학급의 참여보드를 이용합니다. 대시보드에는 별도 도구 카드와 최근 보드 요약이 있습니다. 목록은 보드 메타데이터만 조회하고, 보드 선택 시 게시물, 댓글 창을 열 때 댓글·명단 창을 열 때 학생 명단을 조회합니다. 공유 링크로 로그인하면 해당 보드로 돌아오며 외부 주소로 리디렉션하지 않습니다.

보드 목록 → 보드 → 오른쪽 아래 ＋ 작성창 흐름에 카드·열 배치, 드래그와 이동 버튼, 오른쪽 공유·설정 패널을 제공합니다. 벽·열·격자·표·자유 배치·행·타임라인·스트림·장소 9개 배치와 6색 테마·6캐릭터를 선택할 수 있습니다. 장소 배치는 좌표를 직접 입력하고 선택한 장소의 OpenStreetMap 지도를 여는 방식이며, 지명 자동 검색은 없습니다.

글·사진·영상·음성·문서·링크·투표를 게시하며 음성 녹음, 그림 그리기, 사용자별 글/댓글 초안, 댓글·응원·교사 승인, 익명 표시, 교사의 일괄 공개, 고정·검색·정렬·이동·편집 이력 복원을 제공합니다. 보드 설정 복제는 **내용이 없는 새 보드**를 만듭니다. 보관은 학생에게 숨기며 활동 마감은 읽기를 유지하고 학생 작성을 차단합니다. 공유 링크·QR도 로그인한 해당 학급만 접근합니다. 익명 모드에서도 작성자 본인과 교사는 이름을 확인합니다.

파일은 지원 이미지·문서·음성 100MiB, 영상 250MiB, 글당 10개, 보드당 글 500개, 교사당 참여보드 저장 5GiB입니다. 직접 서명 PUT으로 Vercel을 통과하지 않고 Storage에 올리고, 실제 파일 형식/크기 검증 후 별도 확정 경로로 복사합니다. 사진 미리보기는 최대 640px WebP이며 원본은 유지합니다. URL은 15분만 유효하고 카드 이미지는 지연 로딩, 영상·음성은 자동 다운로드하지 않습니다. 미완료 업로드는 만료 유예 후 후속 업로드 또는 소유 교사 정리 API에서 회수합니다. 별도 예약 정리 작업은 없습니다.

현재 구현은 수업용 보드 기능입니다. Padlet Sandbox·Arcade, 공개 비회원 참여, AI 보드 자동 생성, 외부 LMS/SSO, 오프라인 동기화, 기존 Padlet 데이터 가져오기는 포함하지 않습니다. AI 도구함의 모델은 기존 `gpt-6-luna`이며 참여보드 기본 기능에는 AI 호출 비용이 없습니다.

## 전시 초기 로딩 진단 — 2026-10-13

운영 메타데이터와 응답 헤더로 Vercel Functions `icn1`, Firestore `asia-northeast3`, Storage `ASIA-NORTHEAST3`를 확인했습니다. 모두 서울이며 이번 변경에서 리전·DB·권한 규칙은 변경하지 않습니다. 기존 화면은 `/api/me` → 전체 전시 목록 → 학급별 전시 목록을 순차 호출했고, 빈 전시의 API 응답 시간 합계가 첫 측정 2,979ms, 이후 1,940ms·2,034ms였습니다. 이는 브라우저 렌더링 시간을 포함하지 않은 API 측정입니다.

인증된 전시 API 응답에 학급·전시 목록과 검증된 사용자 역할을 함께 담아 최초 호출을 **1회**로 줄였습니다. 전시 페이지는 별도 `/api/me` 요청 없이 이 응답의 역할을 확인하고, 비로그인·만료는 로그인 화면으로, 정지·역할 불일치는 접근 거부 화면으로 전환합니다. 모든 API의 기존 서버 인증·정지·권한 검사는 유지하며, 독립 DB 읽기는 병렬화했습니다. 새로고침 때는 목록 영역만 로딩합니다. 105개 전시실의 페이지 이어보기·학급 구분·학생 열람 범위·권한 차단과 프로덕션 빌드 브라우저 요청 수를 검증합니다. 실제 운영 측정과 로컬 검증 기록은 Git에서 제외되는 `.qa/loading-audit-results.json`, `.qa/loading-audit-final-results.json`, `.qa/loading-bootstrap-api-results.json`, `.qa/loading-bootstrap-browser-results.json`에 보관합니다.

## AI 서버 설정과 범위

`OPENAI_API_KEY`와 `OPENAI_MODEL=gpt-6-luna`를 서버에 설정합니다. 운영 키는 Vercel Production의 민감 환경 변수이며 `NEXT_PUBLIC_` 변수에 넣지 않습니다. 키 값은 저장소에 포함하지 않습니다. Preview에는 별도로 서버 환경 설정이 필요합니다.

- OpenAI Responses API, `store:false`, 짧은 초안에 제한된 출력 토큰을 사용합니다.
- 기본 한도: 교사당 분당 4회·하루 40회, 앱 전체 하루 400회. 실패한 예약도 포함하고 캐시 재사용은 제외합니다.
- 서버 변수 `AI_TEACHER_MINUTE_LIMIT`, `AI_TEACHER_DAILY_LIMIT`, `AI_GLOBAL_DAILY_LIMIT`로 조절합니다. 일일 기준은 Asia/Seoul입니다. 이는 요청 수 상한이며 금액 기반 결제 차단 기능이 아닙니다.
- 어드민에서 적용 모델·오늘 전체 요청 수·한도를 확인합니다. 입력과 출력의 원문은 운영 로그에 저장하지 않습니다.
- 한도·인증·서버 오류는 실제 실패로 표시합니다. 생성 결과를 학생 평가나 공식 기록으로 자동 확정하지 않습니다.
